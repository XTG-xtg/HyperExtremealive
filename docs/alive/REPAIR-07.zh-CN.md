# 0.5-alive.7 修复与验证

版本号 15。完整范围及未完成项见 `INTEGRATION-MATRIX.zh-CN.md`，不以本页测试通过
代替全功能完成或真机系统集成验收。

## 修复路径

`AliveWallpaperService / AliveHooks -> EngineRegistry -> PhotoPowerGate -> MotionSession -> EglWorker`

保留已有电源保护规则，不把 AOD 可见等同于可交互唤醒。除了补充可选电源方法
名称，还补上真正的渲染端事件消费：旧代码只有照片在隐藏时消费完整事件，其他
引擎只在绘制时看到最后一个状态。现在所有真实引擎消费事件，隐藏时不画，恢复时
按原始事件时间求出正确帧。真实壁纸与预览的暂停语义分开。

CPU 时间线可以在双槽间共享，但渲染器、纹理与 EGL 上下文不共享。新槽回放相同
历史，过期 sequence 不得反转当前状态。新增 LivePowerProbe 在真实 Android Looper、
EGL Worker 和 ImageReader 上检查隐藏时 sequence 已到 4，隐藏期间提交帧数不变，
恢复后球体 scale 回到 0.22。

## 亮度与布局

新 AodPresentation 先解析 MSAA 窗口，再执行 `1-(1-color)^gain`。gain 默认 1.3，
纯黑保持 0，亮部不会简单乘法溢出。系统面板电流、AOD 时长和指纹高亮没有改动。

SystemClockTracker 观察时钟控件的显示坐标，读取平移后的边界，经 ConfigProvider
同 UID / 系统 UID 受限通道发布。实际时钟不被移动或隐藏。锚点类场景采用这些位置；
无可用位置时使用有界分钟位移。诊断页明确显示是否已经读取到系统坐标。
这条 Hook 路径还没有安装到手机系统进程中验证，不应声称已确认匹配所有 HyperOS。

契约，并限制透明背景干预范围，见 `ROM-CONTRACTS.zh-CN.md`。这不是运行时命中证据。

候选 APK 以及合成测试图。没有安装 APK，没有修改实际壁纸、屏幕电源、用户照片或

因此它证明原始效果和适配链能工作，不证明真实 AOD 下系统会按同样帧率调度。

## 照片与 Vivo 扩展

照片新增不可变私有素材文件、独立桌面/相框输入、跟随锁屏开关、独立取景、双指
裁切/相框旋转；补齐磨砂所需纹理，并暴露全屏照片、仅系统时钟、纯色及颜色蒙版。
应用日志先落盘，再更新本地配置；未确认事务在进程重启时恢复旧快照，已确认事务
只做清理。它不保证恢复系统绑定之前的第三方壁纸组件，也不删除用户未应用草稿。

Vivo 原始渲染 APK、两份原生库、纹理包均校验 SHA-256 后加载。Vivo 类加载器只继承
Android 框架，不与本应用/Flyme 的依赖混用。蒙版编辑器沿用 Miuix，U2NetP 模型及
Apache-2.0 说明一起保留。原生库 PT_LOAD 为 64KB 对齐，满足 16KB 对齐条件。

视频测试发现系统 MediaMetadataRetriever/MediaPlayer 在隔离进程读同一有效 MP4 时
返回空元数据/prepare 失败，而 MediaExtractor/MediaCodec 可以正确解析解码。改为
从视频轨道取元数据、必要时直接解码有尺寸上限的封面；纹理视频采用时间戳驱动的
无音频 MediaCodec，并在隐藏时释放。无法生成 HDR 封面时明确报错，不把 HDR 当 SDR。
帧数估算使用四舍五入，避免 2 秒 30fps 因浮点截断得到 59 帧。

桌面照片的首次取景编辑会从当前可见的锁屏照片与裁切开始，滑块和手势采用同一规则，
避免关闭跟随时突然跳回旧桌面图片。旧安装脚本已去掉自动写 LSPosed 数据库和强杀进程。

## 安装后的关键验收

1. 保留原数据覆盖安装（签名不一致则先停止），手动确认推荐作用域并重启一次。
2. 启航/凤凰从桌面息屏至少 10 秒，不应自行展开；亮到锁屏后才展开。
3. 锁屏不解锁再次按电源键；还没展开完立即息屏；连续重复几轮。
4. 测试指纹直接解锁、密码解锁、通知点亮、返回锁屏，以及圆景/留光/新增四种照片效果。
5. 对比 100% / 130% 亮度，观察纯黑背景和系统时钟/指纹亮度是否保持系统行为。
6. 息屏一到两分钟后刷新诊断，确认收到系统时钟坐标；观察时钟和图案位移方向，
   检查是否有重叠、跳位或越界。没收到坐标必须按 Hook 适配问题处理，不能当作已跟随。
7. 单独验收待机温度、电量、AOD 超时、折叠/旋转、进程重建及长时间运行。
