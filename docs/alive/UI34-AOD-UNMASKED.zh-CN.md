# ui34：移除非零亮度下的全屏 AOD 壁纸遮罩

版本：49 / `0.5-alive.7-ui.34-aod-unmasked`。

用户反馈进入 AOD 约两秒后再次变暗，要求尝试移除息屏时系统添加的遮罩。

重启后的 ui32 日志确认：在 5 倍亮度下，系统先请求遮罩 0.5，随后根据显示亮度请求 0.3；模块都输出 0.1，说明会话保持已生效，但仍有残余遮罩。同一时段系统显示亮度从约 98 nits 切入约 32 nits 的 Doze 档位。这两层控制需要分开判断，日志不能证明两秒后的主观变暗只来自遮罩。

ui34 将所有非零亮度下的全屏 AOD 壁纸遮罩目标改为 0，去掉原先 `black / brightness` 的残余压暗。0 仍完全沿用系统原始效果；自定义全黑 AOD、自动关闭显示、其他壁纸和非 AOD 调用保留系统行为。空间、光栅与视差的自绘层使用同一规则；视差自定义全黑过渡保留原始进度。

本机 ROM 的 `doWallpaperBlackAnim` 明确把 0 解释为关闭 wallpaper black 动画通道，继续执行原来的景深通知和 wake-lock 清理；无需跳过整个系统方法。

保留 ui33 的唤醒首帧高曝光撤销修复。本次不修改物理面板亮度，不关闭系统自动亮度，也不改变 AOD 自动关闭时间。新 SystemUI 代码需安装后重启系统界面或手机加载；实机效果仍需用户确认。

本地只读诊断位于 `build/aod-second-dim-20261115/`，不随源码提交设备日志或反编译源码。
