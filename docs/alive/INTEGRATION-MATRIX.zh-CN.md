# OpenAlive 合入清单（0.5-alive.7-ui.3）

## 范围与结论

本轮对照用户提供的 `HyperAlive_Module.zip` 和 `OpenAlive-main.zip`，修改当前
HyperExtreme 源码。**这是修复及扩展候选，不是 OpenAlive 全功能合入完成版。**
不包含小米原有超级壁纸。参考压缩包只解压在忽略目录 `.reference/`，不会打进 APK
或交付源码包；HyperAlive 的旧核心 APK/DEX、签名密钥和自动修改 LSPosed 的脚本均未移植。
Vivo 原始官方渲染运行时则作为此功能所需的明确例外，按 `IMPORTED-VIVO.json` 的来源、
逐文件哈希和隔离类加载规则接入，不加载其应用组件，也不安装或替换系统 Vivo 包。

读取到的连接设备是 Android 17 / API 37，原安装版本是 `0.5-alive.6-ui.2` / 13，
随后用户明确说明自己主动更新到了 `ui.3` / 14，ADB 已再次核实。以用户当前 ui.3
为实机对照，本轮候选仍未覆盖安装，没有改壁纸、重启、清数据或改 LSPosed 作用域。

| Vivo 主体/背景/涂抹区域 | 已接入 | 本机 U2NetP 自动识别、框选识别、画笔、擦除、六步撤销、导入黑白蒙版；真实设备 ONNX 全图/框选推理通过。未确认的画笔笔迹不保证进程死亡后恢复 |
| 通知短暂点亮 AOD、系统光效、Flyme 圆环/双侧光带 | **未接入** | 上游依赖 ColorOS 通知/Doze 接口及官方 SVGA 运行时，需要 HyperOS 专用桥接 |
| Flyme / HyperOS / Vivo 原版时钟字体及编辑器 | **未接入** | 不能把 ColorOS 壁纸应用中的编辑器 Hook 原样放进 HyperOS |
| 时钟颜色、字体、Vivo 玻璃/模糊、解锁和指纹遮罩完整衔接 | **未接入** | 当前只保留系统时钟及观察几何位置，不是替代实现 |
| 独立桌面照片、独立相框照片、跟随锁屏照片选项 | ui.3 按预览状态收敛面板 | 桌面只有「跟随锁屏」开关和「选择照片」设置行，无备注大按钮；开启跟随不清空独立桌面照片/取景/纹理，选图成功才关闭跟随，取消无变更；草稿与应用分离 |

| 小米原有超级壁纸 | **明确排除** | 不打包其应用、渲染器或素材 |

## 接下来完成全量合入需要的工作

1. 安装当前候选并重启推荐作用域后，采集真实的 AOD/锁屏/解锁及系统时钟 View
   结构，验证新 Hook 的命中率和亮屏/息屏顺序，解决实际 ROM 差异。
2. 完成已接入照片和 Vivo 在真实双槽、进程重建、横竖屏、不同自定义素材上的系统级
   回归。未确认的画笔编辑、孤立旧素材回收及多编辑窗口并发仍需继续完善。
3. 验证 Vivo 在真实 Doze 下的动画/视频功耗策略及多个 EGL 上下文的生命周期。
   已通过离屏输入和真实 Worker 换 Surface 测试不代表已测待机耗电，64KB ELF 对齐也不代替 16KB 设备验收。
4. 按 HyperOS 实际通知与 AOD 生命周期实现通知光效，保留勿扰/隐私与系统息屏策略。
5. 对接 HyperOS 时钟编辑器或独立的原版控件承载层，再验证字体、日期农历、动效、
   指纹遮罩与玻璃采样。需分别验证权限、类加载器和系统进程稳定性。

所有新增官方蒙版保留权利说明和 SHA-256，见 `IMPORTED-PHOTO-STYLES.json`。
OpenAlive 自实现代码的 MIT 许可不代表官方素材获得再分发或商用授权。
