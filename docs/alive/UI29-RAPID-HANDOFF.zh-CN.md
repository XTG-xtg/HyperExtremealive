# ui29：连续息屏／指纹解锁的提交保护

2026-11-15，用户报告连续切换时转场偶尔短暂停住、下一次切换恢复，并伴随概率性闪烁。

## 证据与判断

只读获取现有日志、壁纸服务状态与配置；当前为 601 透镜照片，连续 AOD 动画开启。日志未见渲染异常，息屏／解锁状态仍在正常送达。

新增带实际 Looper 调度的 CPU 压测，对透镜及 5 种照片形状分别反复打断 40 轮，共 240 轮，未复现停帧。它不能检验手机的 EGL、BufferQueue 或 SurfaceFlinger 交接，因此没有将 CPU 测试通过视为实机问题已消失。

代码审查确认：主线程已收到隐藏、OFF 或新场景时，GL 线程仍可能正在渲染旧场景；原先正式绘制及 swap 前主要依赖已被 GL 队列消费的状态，缺少最新事件校验。另一方面，FramePump 已负责 vsync 调度，但 EGL 仍固定 swap interval 1，提交阶段可能再次等待同步。

## 修改

- 绘制前、提交前都核对主线程最新可见性、显示状态和场景序号。过期帧丢弃，由已排队的状态事件请求最新帧；不等待用户再按一次电源或指纹。
- 隐藏及 OFF 请求立即使普通绘制失效，减少向已停用窗口队列提交旧帧的机会。隐藏预热仍沿用独立的严格条件。
- 使用 EGL 配置允许的最小非负 swap interval，由 FramePump 统一控制绘制节奏；设备支持时选 0，减少提交阶段等待。保持每次只挂一个帧请求、稳定场景停绘及有界兜底策略。
- 保留 ui28 取消额外 150ms 起步等待的改动。
- 诊断增加绘制阶段、被丢弃帧数、最近提交时间、最长 swap 耗时和实际配置的 swap interval。状态查询提供可直接读取的 `home_frame_state` / `lock_frame_state`；超过 100ms 且刷新最大耗时的 swap 会记录日志。

## 验证边界

回归覆盖最新显隐／OFF 请求在 GL 队列处理前阻止提交、500 组 AOD／HOME／AOD 过期场景、100 组丢帧后自动请求最新帧，以及已有帧调度、时间线、解锁时机及电源保护。

日志、CPU 压测和 JUnit 结果保存在 `build/aod-stuck-stress-20261115/`。此次只读取手机诊断并安装候选，未代用户触发息屏／指纹测试。系统合成层的概率性停顿与闪烁是否消失，需要用户继续实测；如果复现，新诊断可区分等待提交、缺帧与场景错误。
